# 桌面客户端显示与捕获防护

## <a id="case-scope"></a>案例对象与证据范围

一款受管浏览器式桌面客户端中，普通页面可见，受保护业务页在原生远程桌面里全白，在截图和另一种远控里却是黑帧或捕获失败。切换远程桌面时曾短暂看到内容。用户没有观察过物理显示器；现有登录后来又受到无法重新认证的约束。

本案先做网络、前端、桌面捕获对照，再追到客户端自己的原生显示保护，经过明确授权完成当前进程的可回滚验证；随后只读核对录屏、诊断、上报和模块阻止能力。

> 案例依据为获授权的程序副本、PE 元数据、嵌入接口描述、受限反汇编、只读运行字段、日志元数据和实际画面。业务名称、站点、身份、构建指纹、固定地址及补丁载荷均已移除；原始材料留在任务私有目录，不随技能发布。下文记录这次验证覆盖的范围，不构成其他产品或版本的通用结论。

## <a id="display-paths"></a>显示链与捕获链

先把观察对象分开，记录使用的会话和取图方式：

| 现象或证据 | 本案支持的判断 | 需要另外核对的对象 |
|---|---|---|
| 首页和启动资源可获取 | 网络路径至少能完成这些请求 | 页面执行、视图是否显示、业务登录 |
| 匿名代理请求返回认证挑战 | 服务要求认证 | 客户端实际携带认证后的结果 |
| 某接口返回未登录状态，但前端代码有容错分支 | 该状态未必阻断整页布局 | 实际执行路径和异常 |
| 开发者面板空白，面板参数明确被禁用 | 调试界面受到管理 | 渲染和 GPU 状态 |
| 同一工具能截普通页，受保护页拒绝或全黑 | 捕获结果具有页面选择性 | 窗口捕获亲和性及独立的远程显示逻辑 |
| 原生远程桌面白屏，截图通路黑屏 | 两条输出路径有不同表现 | 是否分别隐藏视图、排除捕获 |
| 重连时内容闪现后消失 | 动态状态更新值得优先追踪 | 哪条回调更改了显示状态 |

早期按网络线索对少量网关做临时定点绕行，实际新连接已走对照路径，问题仍在，测试配置随即撤回。故障又早于透明代理开启。后续停止把透明代理、匿名认证挑战或单个非成功响应当作根因。

> 早期网络日志采集曾在明确授权后正常重启客户端，并再次正常重启以结束采集。进入保留既有登录的约束后，后续恢复没有再依赖重登、清缓存或重启。保留的是具体阶段的承诺，不能改写成整个排障过程从未重启。

### <a id="observation-channel"></a>桌面观察通道

跨账户、跨宿主接入桌面工具时，先确认执行账户、交互会话、窗口归属及进程完整性级别。普通页成功取图是对工具链的对照，目标页失败才有判别力。

本案通过授权的 SSH 标准输入输出通道桥接到正确的 Windows 身份。GUI 子系统程序没有按预期输出协议时，显式创建子进程管道，再透明转发字节；仅新增相应工具接入配置。辅助工具的接入配置与目标程序的临时内存改动分开留档。

交互桌面不可用或拒绝访问时，停止发送键鼠输入。只读系统状态可以继续核对；恢复访问后重新观察窗口和控件，再决定下一步。某次拒绝访问后来与会话断开、锁定一致，另一些时点的原因未完全确认。

## <a id="native-evidence"></a>原生实现的静态证据

### <a id="artifact-identity"></a>构建身份与工具覆盖

取得授权程序副本后，记录文件摘要、格式、架构、版本和副本来源。仅复制分析所需程序，不把用户数据目录一起带走。原件和副本的身份记录保存在私有任务材料里。

本案实际运行了 REA 的 PE 头、节和资源检查。当前提供程序没有可用的完整反编译能力，地址范围也不属于该命令的输入，因此后续函数语义来自另行实施的有界 GNU 反汇编、节映射、异常展开表及引用解析。

> 工具执行证据只证明它实际完成的操作。帮助文本、资源解析成功或全部可见接口描述可解析，都不能替代控制流分析。缺失的 `artifact_changed` 或提供程序版本字段按未知处理，不从空字段推导“原件变了”或“已确认版本”。

### <a id="registration-chain"></a>接口注册到系统调用

用具名接口和错误文案作为锚点，逐段追踪：

```text
接口描述与参数类型
  → 名称对应的注册记录
  → 工厂与对象构造
  → 虚表处理入口
  → 参数解析与策略分支
  → 具体视图方法或系统 API
```

本案分别找到普通捕获保护接口和远程会话保护接口。前者最终选择传给 `SetWindowDisplayAffinity` 的参数；后者进入另一条状态更新路径，最终对内容视图调用 `SetVisible(false)`，并使用背景色填充窗口区域。

- 普通捕获路径在允许捕获和 `WDA_EXCLUDEFROMCAPTURE` 之间选择。运行查询实际返回了 `0x11`，与捕获被拒绝或黑帧相符。
- 远程显示路径根据客户端保护状态与远程会话检测结果，隐藏原生内容视图。它独立于普通捕获设置，解释了原生远程桌面里的白色区域。
- 视图隐藏不是网页没有下载，也不是业务登录被跳过。恢复原生视图后，网页自身的登录弹窗仍然存在。

> `0x11` 是窗口捕获设置的证据。它在某一系统和捕获方式下的结果，不足以解释所有远控协议；白屏与黑帧的独立根因来自上述调用链和运行验证，而不是颜色类比。

### <a id="address-mapping"></a>地址与函数边界

先区分文件偏移、RVA、首选虚拟地址和运行地址：

```text
RVA = preferred_VA - preferred_image_base
live_address = loaded_module_base + RVA
file_offset = section_raw_offset + (RVA - section_virtual_address)
```

文件偏移公式仅用于落在对应节原始数据范围内的地址。运行时读取必须重新取得实际模块基址；字符串地址、指向字符串的表项和表项指向的函数地址分别标注。

用 PE 的异常展开信息约束单次反汇编范围，再检查尾调用、funclet、间接跳转和数据块。范围信息提供分析边界，不自动赋予业务语义。整库字符串命中和大段反汇编都不能替代接口注册与具体调用点的关联。

## <a id="bounded-runtime"></a>有界运行对象核验

静态路径明确后，才读取当前进程的最小状态。本案沿已定位的窗口注册容器，取得控制器、浏览器窗口接口和内容视图，并交叉核对：

- 原进程标识、创建时间、文件摘要和模块范围；
- 注册项数量与合法范围、窗口归属和窗口标识；
- 虚表、已确认的 getter 以及内容视图类型；
- 捕获保护、远程保护、远程会话检测和可见性布尔字段。

这一阶段只读确定语义的指针与标量，没有扫描堆、提取网页内容、调用目标内部函数或附加调试器。记录每次读取的字节数和时点，防止把不同状态快照拼成一个原子事实。

> `visible=true` 只说明对象状态；实际画面仍要通过对应远程通路观察。客户端“请求捕获保护”的布尔值也不一定等于操作系统此刻保存的窗口亲和性。

本案另有长时采样在工具层超时，完整输出未取得。后续确认采样进程已经结束，只报告实际拿到的离散状态和用户画面确认；脚本计划采样的次数与时长不作为已通过的验证结果。

## <a id="runtime-adjustments"></a>授权下的运行时验证

### <a id="state-writeback"></a>状态字段与策略回写

最初仅调整少量运行字段，正常界面更新后一度恢复显示，但客户端随后重新写入保护状态，问题复发。数据字段写入也不会自动执行视图重绘。

判断短暂恢复时，分别检查：目标字段是否被写回、视图更新是否发生、正常策略回调是否重新执行，以及实际远程画面是否变化。将“字段改过”与“画面已恢复”分开验收。

### <a id="code-change"></a>最小代码调整

在用户明确允许本地保护调整后，本案只对已证明语义的条件分支做当前进程内修正，使该远程隐藏条件落到显示路径，保留其他隐藏条件与普通捕获路径。指令长度和位移保持不变。

这种处理依赖前导比较指令的标志位、输入字段值域和后继控制流。即使只改一个字节，也需要重新验证具体构建；不能把某个跳转操作码当作通用替换模板。

执行过程按事务处理：

1. 校验原进程、创建时间、模块身份、对象类型、完整指令上下文与预期原值；不匹配即停止。
2. 在写入前保存原字节与原页权限，备份与具体进程实例绑定，防止覆盖旧备份或误用于新实例。
3. 只临时调整现有映像页权限，以 `WriteProcessMemory` 写最小范围，回读校验，并执行 `FlushInstructionCache`。
4. 恢复原页权限，再用 `VirtualQueryEx` 核验；恢复权限失败属于事务失败，而不是成功后的附带警告。
5. 失败时分别尝试恢复原字节和原权限，并分别回读。若字节已恢复、页权限仍异常，恢复入口还需支持仅恢复权限。

没有新增目标内可执行内存区、创建远程线程或暂停目标进程；这些边界也不构成并发安全保证。最终调整仅对当时进程有效，没有修改磁盘程序、服务器策略或设置开机补丁。

> 后来发现的审计、完整性比较或安全代理仍可能观察这类内存差异。磁盘签名有效与运行中代码未变化是不同命题，恢复页权限也不会消除历史记录。

### <a id="capture-reapply"></a>捕获保护的重新应用

远程画面恢复后，普通截图仍然失败，证明此前修正没有顺带解除捕获限制。用户另行授权后，才临时调整捕获参数的选择点，使正常调用传入允许捕获的值；通过已有非保护标签与保护标签之间的切换触发客户端正常回调，取得了真正的目标页面画面。

恢复时先还原原字节和页权限，再触发正常设置路径，最后只读确认实际窗口亲和性回到 `0x11`。原远程显示修正保持不变。

代码参数决定后续调用，窗口亲和性保存的是已应用状态，两者存在时间差。因此验收分别覆盖：

| 层次 | 核对对象 |
|---|---|
| 代码 | 原指令或授权修改值是否回读一致 |
| 内存映射 | 现有页是否恢复原保护属性 |
| 系统状态 | 当前窗口的实际捕获亲和性 |
| 行为 | 对应页面在实际远控或截图中是否可见 |

后续用户又选择在当前进程里持续允许截图。代码调整已保留，但桌面不可访问时，系统仍可能保留上一次亲和性，持续模式后的真实帧验证没有完成；不能把参数写入成功改述为已经持续可捕获。允许截图本身不启动录屏，不过也不只授权某一个自动化工具。

> 临时恢复任务应先做语法检查。Windows PowerShell 读取无 BOM 的 UTF-8 中文源码曾导致任务在执行恢复前解析失败，随后改用 ASCII 源码并手动恢复、重新核验。一次性任务宜用按需启动或及时移除触发器，避免到时重复执行却只因结果已存在而失败。任务返回码、结果文件和实际状态分别核对。

## <a id="recording-reporting"></a>录屏、诊断与报告行为

将证据拆成四个问题：程序有没有能力、配置是否允许、当前是否执行、数据是否被接收。它们不是同一条结论。

| 对象 | 本案核实到的证据 | 仍然未知或不支持的推断 |
|---|---|---|
| 桌面／标签采集与媒体编码 | 通用浏览器框架包含相关接口和编码实现 | 存在接口不证明厂商正在录像 |
| 类似录屏状态的日志布尔字段 | 抽取到的字面量为假，但未在选定程序副本找到定义 | 字段可能来自扩展、其他组件或网页，其语义尚不明确 |
| 专用诊断 Capture 接口 | 注册、工厂、处理函数和服务调用相连；场景是基础诊断、Trace 和网络日志 | 没有因此建立视频采集链；自定义 Trace 参数的全部数据范围也未确认 |
| 日志上传的 snapshot 分支 | 接口枚举和分支存在，关联标签与进程／对象调用 | 尚未追到像素、帧、视频编码或媒体输出，不能直接翻译成截图或录像 |
| 厂商诊断包 | 原生函数按时间范围从日志表取消息，并组装日志、转储、系统及设备信息 | 没有闭合该打包函数的自动触发和本次上传链 |
| 行为日志 | 现成日志反复提示该行为上报通道未开启 | 仅描述该通道，不覆盖其他报告功能 |
| 崩溃报告 | 本地实现与随附格式交叉核对；数据库全局非空，设置中的上传允许位为真 | 上传许可不代表某份报告已发送或被接收 |
| 崩溃上传尝试时间 | 所检查设置记录的最近尝试早于本次内存调整 | 只覆盖这份设置和该记录语义，不排除其他数据库或通道 |
| 企业事件报告 | 处理函数先取得报告设置，再检查允许事件集合，满足后才走实时报告边界 | 用户偏好及已知策略位置未见配置，不覆盖所有运行或云端策略存储 |
| 第三方模块阻止 | 初始化状态为真，所读阻止计数为零；导出 getter 与计数更新实现已关联 | 模块装载阻止不等于对现有代码页做自校验 |
| 本地安全事件 | 限定时段和事件类别中，没有明确关联此次调整的告警 | 本地未见告警不等于没有其他日志或远端记录 |

崩溃设置采用只读文件句柄，在校验格式标识、版本和长度后，仅定点读取允许位与尝试时间，跳过客户端标识。某些看似只读的库 getter 在文件损坏时会恢复写盘，不能仅根据函数名假定无副作用。

日志里的非终止式检查错误在修改前已出现。核对首见时间、来源及变化后，仍未建立它与本次修改的因果关系；原进程持续存活也不代表全部运行状态毫无异常。

系统隐私许可历史只发现自动化工具的一次已结束屏幕捕获条目，没有匹配到目标客户端。该观察不覆盖所有桌面复制、驱动或自实现采集通路。会话中请求的是单帧截图，未启动持续录像；工具内部与其他软件的全部行为不在这个结论范围内。

最后尝试查看浏览器现成的媒体诊断页时，桌面工具在输入前返回拒绝访问，没有创建临时标签，因此没有取得当前媒体流计数。归档保留这一缺口，不用接口存在、零日志命中或直觉估计“开启概率”。

## <a id="rdp-transport"></a>远程连接的独立故障

排障期间还发生过“远程桌面连不上”。这与页面区域白屏分开处理：

- 查询服务与真实监听，确认来自指定客户端的 TCP 连接曾到达；核对回程路由。
- 查询对应连接窗口的远程桌面事件及认证事件，并说明时段和查询上限。
- 对服务器回环地址发送无凭据的 X.224 协商，再完成 TLS 握手；在 NLA 登录前结束，不提交账号或密码。
- 此次探针仅在自己的进程里跳过自签证书验证以测试握手能力，未修改系统信任或客户端配置；测试成功不验证远端客户端的证书判断、链路质量或用户登录。

用户随后自行重新连上；期间没有重启远程桌面服务、注销会话、重置密码、降低认证要求或调整网络设置。原客户端进程和登录继续保留。这段按未归因的连接暂态记录，不能冒充已修复网络根因。

## <a id="case-results"></a>案例结果与覆盖

- 原生远程桌面白屏已通过静态调用链、运行字段、用户实际观察交叉定位到独立的视图隐藏保护；授权的当前进程调整恢复了远程可见性。
- 普通捕获保护是另一条路径。临时允许捕获后取得真实目标画面，并验证了恢复原保护；后续持续模式只确认代码调整，未完成最后的真实帧复验。
- 确证了诊断打包、上传接口、崩溃上传许可和模块阻止框架；没有确证正在录制或上传屏幕视频，也没有闭合针对此次代码差异的检测、告警、上报链。
- 加密扩展、未覆盖组件、全部动态调用、外部安全代理及服务器审计仍是覆盖缺口。没有为补齐这些缺口解密扩展、抓取凭据、主动触发录屏或调用上传接口。
- 临时只读／恢复任务已经核对并注销，原始证据和恢复备份保留。辅助工具桥接配置仍存在；进程内修正不跨重启或更新生效。
