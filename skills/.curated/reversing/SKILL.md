# Reversing

静态逆向一个已发行的移动应用，回答三件事：**能读到什么、读到的东西怎么证明、结论怎么汇报**。

## <a id="scope"></a>能力边界

本 skill 只覆盖静态分析，不涉及动态调试与运行时 hook。

只读分析与改包分发是两件事。前者不改原包，没有签名问题；后者会让原签名失效，无法覆盖安装原包、触发安全提示，还涉及版权与分发边界。汇报时不要把两者混在一句话里。

- [爱养成系列](references/aiyangcheng.md)：单个应用族的完整还原实例，并规定结局达成条件的汇报格式。用户问"某结局怎么达成"时，按[结局达成条件的汇报格式](references/aiyangcheng.md#report-format)回答。

## <a id="working-rules"></a>工作原则

- **分层后再判断。** Dex、native 与 assets 都要检查；符号表通常是 native 代码最省力的入口，但"规则在 native 层"只是引擎类应用的常见形态，不是定律。
- **界面缺失以渲染函数为准。** 数据表只能说明字段存在，不能证明界面是否会显示；已知成因与排查链见[从界面文案反查数据与代码](references/apk.md#ui-to-data)。
- **结论必须可复核。** 每条判断落到函数、地址或数据表行，实测与推断分开标；能重建输出时，用还原器与应用实际显示逐条对照，闭合证据链。
