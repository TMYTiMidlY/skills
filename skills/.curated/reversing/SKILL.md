# Reversing

逆向分析一个已发行的应用，回答三件事：**能读到什么、读到的东西怎么证明、结论怎么汇报**。按应用形态选择移动端静态分析、设备侧取数或桌面客户端取证流程。

## <a id="scope"></a>能力边界

默认离线或只读。移动端流程以静态分析和已授权的设备侧取数为主，不默认开展动态调试与运行时 hook；桌面流程先建立静态调用链，再核对少量已确定语义的运行字段。

只读分析与改包分发是两件事。前者不改原包，没有签名问题；后者会让原签名失效，无法覆盖安装原包、触发安全提示，还涉及版权与分发边界。汇报时不要把两者混在一句话里。

桌面取证保留既有登录和远程访问。重启、注销、修改保护或策略、写进程内存、启用诊断采集和上传都是另外的操作，先说明对象、影响与授权范围。本地保护调整不授权读取或转移凭据、关闭审计、隐藏改动、解锁桌面或改变服务器策略。

运行时修改需要可核验的原值备份和恢复路径。厂商支持、并发安全、反篡改及后续版本兼容性分别说明，不承诺零风险或远端无感。

## <a id="working-rules"></a>工作原则

- **分层后再判断。** 移动端检查 Dex、native 与 assets；桌面端区分原生模块、接口描述与页面资源。符号表通常是 native 代码最省力的入口，但"规则在 native 层"只是引擎类应用的常见形态，不是定律。
- **界面缺失以渲染函数为准。** 数据表只能说明字段存在，不能证明界面是否会显示；已知成因与排查链见[从界面文案反查数据与代码](references/apk.md#ui-to-data)。
- **结论必须可复核。** 每条判断落到函数、地址或数据表行，实测与推断分开标；能重建输出时，用还原器与应用实际显示逐条对照，闭合证据链。构建身份和原始证据保存在任务私有目录，知识库只保留脱敏后的机制与流程。
- **桌面行为分层验收。** 从注册、工厂、虚表和处理函数追到系统 API，分别核对资源加载、视图可见性、窗口捕获、远程显示及连接认证。能力存在、配置启用、当前执行和实际外传分开记录。
- **授权验证采用最小事务。** 先只读匹配当前进程和对象，确需写入并获授权后，保存原值与页权限；写后回读、刷新指令缓存、恢复并核验页权限，最后检查系统状态和真实画面。保留覆盖缺口，不把字段变化或参数写入当成行为验证。

## <a id="related"></a>相邻能力

- `network` 处理远程入口、路由和 RDP 传输；监听或 TLS 检查通过后，仍要单独验证登录和会话恢复。
- `software` 处理分析工具和运行环境；`mess` 保存按症状检索的故障摘要。
- 写入或审查知识库时使用 `manage-skills`，不把任务私有证据、目标地址或可直接套用的补丁载荷放入通用技能。
