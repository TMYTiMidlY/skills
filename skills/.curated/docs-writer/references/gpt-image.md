# GPT Image 生图与修订经验

记录 GPT Image 的素材准备、比例与像素控制、定向修改、重新生成和透明拆图经验。prompt 指提交给模型的提示词。

调用协议、订阅鉴权和 API 参数见 harness skill 的“Codex 订阅生图接入”；内置工具的执行过程和推理配置见其“Codex 运行时笔记”。

> 资料核对日期：2026-09-09。社区经验注明适用环境，未经对照验证的技巧标为待验证。

## <a id="interaction"></a>聊天式执行与思考档位

截至 2026-09-09，OpenAI 官网列出的主力通用模型包括 **GPT-6 Astra** 和 **GPT-5.6 系列**。Astra 面向复杂推理、编程和端到端任务；GPT-5.6 Sol 面向复杂专业工作，Terra 平衡能力与成本，Luna 是该系列中最快、成本最低的模型。GPT-5.5 等较早模型在部分支持的产品中仍可使用，具体以账户显示为准。

这些语言模型负责理解要求和调用工具，实际绘图交给 GPT Image。图像模型包括 GPT Image 2，以及 GPT Image 2.5 的 Flare、Sunburst：Flare 侧重快速日常生图，Sunburst 侧重生成与编辑质量。

> 来源：[官方模型目录](https://developers.openai.com/api/docs/models)及 [ChatGPT 模型说明](https://help.openai.com/en/articles/20001354-gpt-56-and-gpt-6-pro-in-chatgpt)。Chat、Work、Codex 和 API 的可用模型随套餐及开放进度变化；Terra、Luna 的手动选择主要见于 Work、Codex 和 API。

ChatGPT 官网把 GPT-5.6 Sol 的 Medium 称为“标准推理”，High 称为“扩展推理”（Extended reasoning），Extra High 为最高推理强度；Pro 则用于困难任务和较长时间的工作，可选 GPT-5.6 Sol Pro，以及由 GPT-6 Astra 驱动的 GPT-6 Pro。因此，日常所说的 **GPT-5.6 Sol High**，就是使用 Sol 并选择 High。

> 以上采用官网 [速度与推理级别](https://help.openai.com/en/articles/20001354-gpt-56-and-gpt-6-pro-in-chatgpt) 的表述；Pro 选项是否可用取决于套餐和模型权限。

常规生图使用 GPT-5.6 Sol 的 High 档位，保持 Chat 聊天方式，不自动切换 Pro 或展开长时间 agent 任务。素材齐全后直接调用生图，只做必要的预处理、像素调整和透明度检查；搜索研究及额外生成由用户提出。多张独立图片按 [并行生成](#parallel) 分派。思考档位影响需求理解和工具调用，成图质量仍需检查实际输出。

## <a id="canvas"></a>画面比例与交付像素

画面比例决定构图形状，像素宽高决定图片尺寸。修改参考图时，默认保持编辑目标的比例、取景和主体布局；改变比例需要用户明确要求。

### 输入与输出的尺寸记录

图片可能在上传、预览或工具传递时被缩放。应分别记录原始素材、实际输入、原始生成结果和最终交付文件的宽高。中间传输尺寸无法获取时，标为未知；文件尺寸以实际读取结果为准。

输入像素可以变化，前提是比例仍符合要求。检查前统一图片方向，按 EXIF（图像元数据）中的方向标记处理旋转，再比较显示宽高。

### 同比例缩放

有明确最终像素要求时，先按目标比例生图，再用代码将合格结果等比例缩放到准确宽高。

例如，`2048×1152 → 1920×1080` 均为 `16:9`，缩放可完整保留画面范围，无需裁剪或补边。缩小会重采样细节，放大只增加输出像素数量；原始生成尺寸和缩放后的交付尺寸应分别记录。

严格判定同一比例，可检查：

```text
生成宽 × 目标高 == 目标宽 × 生成高
```

保留原始生成文件，从它另存缩放结果，最后重新读取宽高。透明图还要保留 alpha（记录每个像素透明程度的通道），并检查缩放后的边缘是否出现杂色。

### 比例不符

比例不符时，先报告偏差及处理选择。裁剪会删去部分画面，补边会增加空白或边框，生成式扩图会补出新内容，非等比例拉伸会改变物体形状。这些操作均需用户同意，不能直接用于凑交付尺寸。

例如，社区报告的 `1672×941` 接近 `16:9`，但两者存在小幅差异。若用户接受取整容差或轻微形变，可按约定适配，并说明处理方式。

整图缩放会改变像素值。任务同时要求准确交付尺寸和“未修改区域逐像素不变”时，应先确认两者的优先级。

## <a id="reference-geometry"></a>参考画布与比例变更

参考画布可能影响模型选择的构图和输出尺寸。检查结果时，应分别判断比例是否相同、宽高是否相同；如果参考图本身采用常见生成尺寸，还需排除输出恰好落在同一尺寸的情况。

### 保持原画布

明确指定哪张图片是编辑目标，并要求保留画布边界、取景和构图。使用多张参考图时，逐张说明用途，区分编辑目标、布局参考和外观参考；要求冲突时，指定各项属性以哪张图为准。

> 参见官方 [输入图用途说明](https://github.com/openai/codex/blob/20f109eadb9b45360e6ca4f1dee2e82c83a48f7a/codex-rs/skills/src/assets/samples/imagegen/SKILL.md#L95-L113)。

> 本次检索尚未证实“第一张或最后一张参考图决定尺寸”。其他图像模型的空白画布经验，需要在 GPT Image 的实际使用环境中另做验证。

> [Codex 尺寸控制报告](https://github.com/openai/codex/issues/28723) 记录了请求 `2160×3040` 却返回较小图片的情况，测试范围为两个订阅调用入口，未比较不同参考图的影响。[ChatGPT 尺寸观察](https://www.reddit.com/r/ChatGPT/comments/1stp4t7/resolution_observations_in_the_image_20_model/) 报告部分输出约为 157 万像素；这项用户观察限于原帖所述时期，本文仅核到可检索文本，未独立下载其文件验算。

### 预拉伸版式参考

参考图与目标比例不同时，可在允许重排和中间变形的条件下，尝试“预拉伸副本 → 模型修复与重排 → 验收”。预拉伸通过分别调整宽高改变画面形状，原始素材保持不动。

1. 制作目标比例的副本，标明它是“经过预拉伸的布局草案”。
2. 为人脸、产品、Logo 和文字等重要元素提供未变形的原始素材或已确认标准参考，说明各自控制的属性。
3. 要求模型在目标画布中合理排版，恢复自然的物体形状；允许内容位置随版式调整。
4. 检查输出比例、物体形状、文字和布局。若仍有明显变形，保留结果并报告，不再拉伸成品来掩盖问题。

这项技巧仍待验证：模型可能保留失真，也可能恢复原构图或原比例。

> 官方 [GPT Image 提示指引](https://developers.openai.com/api/docs/guides/image-prompting?model=gpt-image-2.5) 展示了草图与布局参考的用法。本文尚无“GPT／Codex 稳定修复预拉伸输入”的对照实验依据。

## <a id="standard-reference"></a>单元素标准参考图

为画面中有明确外观依据的元素保留对应素材，每次生成附上当前采用的版本。原始参考模糊或不完整时，先制作一张清晰、完整的单元素参考图，确定外观后再用于整页生成。这种可重复使用的视觉基准称为“标准参考图”。

- 列出要保留的外观和待补充的部分。身份、产品结构、Logo、文字等关键未知信息先向用户确认。
- 生成只包含该元素的候选图，完整呈现所需范围，采用清楚的视角与背景。额外场景、角色或多视图展示按具体需求添加。
- 将补出的部分标为设计补充或推断，供用户审核。
- 用户确认后记录版本，将其设为该元素后续生成的主要依据。
- 整页生成使用标准参考；原始素材留档，回查时再按明确用途附上。

> 官方 [可复用角色参考示例](https://developers.openai.com/api/docs/guides/image-prompting?model=gpt-image-2.5) 展示了先建立角色、再用于后续画面的做法。社区 [多参考与局部编辑讨论](https://community.openai.com/t/how-to-preserve-images-during-edits/1392634/6) 也报告了参考特征混合和身份变化，因此标准参考的作用仍需通过成图检查确认。

## <a id="local-edits"></a>生图流程

按当前需求选择首次生成、定向修订或重新生成，使用对应的图片和提示词。

### 首次生成

提示词写清画面内容、比例、风格、文字和必要限制，附上涉及元素的当前有效素材。确认生图工具实际收到图片；只写文件名或“照以前的素材”容易遗漏输入，附图失败时先停止生成。

> 社区 [参考图读取失败的报告](https://github.com/openai/codex/issues/30121) 描述了特定版本中未成功附图却继续生成无关图片的情况。

### 定向修订

使用当前认可的图片，一次只改指定的一两个元素，同时列出保留要求。

```text
编辑目标：所附的当前认可图片。
本次只修改：元素 A 的指定属性、元素 B 的指定属性。
保留：其余元素、文案、画面比例、镜头、背景和布局。
关联变化：明确是否允许修改目标元素的阴影、反射或遮挡。
交付：完整成图；不得额外裁剪、补边或改变取景。
```

检查修改结果及其周边。质量稳定时可以继续编辑上一张合格图；出现累计噪点、人物外观变化、产品变形或重复错误时，停止沿用失败图。

> 官方 [局部编辑说明](https://developers.openai.com/api/docs/guides/image-prompting?model=gpt-image-2.5) 提醒，仅靠提示词无法保证像素级保留；严格保护其他区域需交给支持图层和蒙版的编辑工具处理。

### <a id="regeneration"></a>重新生成

把已批准的修改合入完整提示词，使用原始素材或已确认标准参考重新生成，排除失败成品。用同一 prompt 再生成一张时，也不自动附上上一张输出。

只有明确要求“不用任何参考图”时，才采用纯文字生成，并接受人物或产品外观可能变化。指令同时要求排除全部图片和使用原始参考时，先确认输入选择。

换模型或新开会话时，重新附上完整提示词和有效素材，保留旧会话与文件。新会话可能减少过时指令干扰，但成图仍需检查；平台无法排除历史图片影响时，应说明限制。

> [连续编辑颗粒化报告](https://community.openai.com/t/multiple-gpt-image-1-high-fidelity-edits-lead-to-grainy-result/1320474) 涉及 2025 年 GPT Image 1 API 和部分 ChatGPT 使用情况，也有新会话重传仍失败的反馈。[Codex 错误版式讨论](https://community.openai.com/t/codex-image-generation-becomes-infographic-locked-after-a-render-error/1383606) 在 2026 年 6 月报告新会话有时暂时缓解问题。是否回退及重新生成的效果，应按实际偏差判断。

## <a id="alpha-layers"></a>透明 PNG 与图层拆分

拆图交付包括背景板和需要独立使用的元素。每个元素单独保存为透明 PNG，后续排版、图层组合由 Canva 等编辑工具完成。

### 真实透明度

生成独立元素时，明确要求背景完全透明，保留主体和必要的半透明边缘。棋盘格是图片查看器显示透明区域的常见方式；如果模型把格子画成实际背景像素，这张图就需要返修。

检查文件本身及其显示效果：

- 读取图像数据，检查透明背景区域的 alpha 值。RGBA 包含红、绿、蓝和透明度四个通道，即使文件为 RGBA，也可能所有像素都不透明。
- 确认主体仍然可见，背景透明；检查头发、玻璃、软阴影和抗锯齿边缘的过渡。
- 在图片查看器中切换黑、白等预览底色，检查棋盘格残留、白边、彩边和漏抠。
- 保存或缩放后复查，确认透明通道没有在处理中丢失。

假透明可以通过重新生成或经授权的精细抠图处理。按颜色删除全图白色、黑色或灰色可能破坏主体和文字；纯色抠像需要背景颜色与主体可分离，复杂半透明材质需另行处理。

> 官方 [透明资产与校验说明](https://developers.openai.com/api/docs/guides/image-prompting?model=gpt-image-2.5) 要求检查解码图像的 alpha，包括头发、玻璃、阴影和物体边缘。

### 图层交付

先明确需要拆出的元素，以及阴影、反射是否随元素一起保留。分别检查背景板是否留下待移除物体，元素是否完整、外观是否符合参考，文字和 Logo 是否正确，边缘是否干净。

生成后的素材分别交付即可，无需叠回原图或制作复合对比。文件名应能识别对应元素；画布大小和留白按后续编辑需要确定，额外的位置或层级信息按需提供。

> 扁平图片只保留最终可见内容。被遮住的背景或元素部分需要估计补绘；需要精确保留隐藏结构时，应补充源文件或更多参考图。

## <a id="parallel"></a>多张独立图片的并行生成

用同一个 prompt 同时生成多张独立图片时，由主执行者分派给多个子智能体（subagent）。每个子智能体接收独立输入，只执行一次单图任务；总数量和并发安排由主执行者管理。

1. 为每个子任务提供相同的单图提示词、必要参考素材和独立输出位置。
2. 只传单图所需内容，省去“同时生成多张”“给几个版本”等批量指令。要求一张完整成图，禁止拼图、分屏或多版本展示板；用户明确需要拼版时另行处理。
3. 子任务仅负责生图和必要检查，不扩展搜索，也不继续创建子智能体。
4. 主执行者收集文件，逐张核对尺寸、比例、参考一致性和透明度，防止覆盖或拿错结果。
5. 子任务无法生图或并发受限时，说明情况并商定分批、串行方式。调用超时后先查任务状态和已有结果，再决定是否重试。

子任务示例：

```text
使用下面的提示词和所附参考素材，生成一张完整、独立的图片。
不要拼图、分屏或多版本展示。
保存到本任务指定的位置，报告未经后处理的原始输出尺寸。
```

多图挤在同一固定像素画布中，每张子图分到的像素会减少，切出后放大也无法补回缺失细节。独立调用保留每张图的完整画布；若希望版本间有明确差异，再分别指定要变化的内容。

## <a id="handoff"></a>交付记录

保留完整提示词、当前参考素材和原始生成文件，便于继续修改或交接。交付时说明文件位置、实际宽高、必要的缩放或抠图，以及尚未解决的问题；透明素材附上 alpha 检查结果。
