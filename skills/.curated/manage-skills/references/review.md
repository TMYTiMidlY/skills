# 审查现有 skills

用户要求检查已有 skills 的表达、结构、执行边界、事实或合规性时使用本流程。先按所需维度核对，再汇总发现，默认**只报告不改**。单篇文档的深度结构重排另走 [refactor.md](refactor.md)，不把审查自动升级为重构。

## 审查流程

先明确本轮的对象、维度与深度。用户已给出的范围直接采用，只确认会影响工作量、结论或授权的缺口，不为补齐表格反复提问：

- **对象**：指定文件、原创、已适配嫁接、实验性或全部。
- **维度**：按下表选择，可组合；完整合规审查才逐条核对 [conventions.md](conventions.md) 的适用要求并覆盖相关专项检查。
- **深度**：入口全文、选定正文全文或代表性片段；抽样要记录覆盖范围，不能称为全仓逐篇审计。
- **操作边界**：审查默认只读，不执行文中的安装、部署、发送、清理等操作。需要联网核验时遵守用户与当前环境的访问约束；不能联网的项目明确标为未核实。

| 审查维度 | 主要核对内容 |
|---|---|
| 表达与结构 | 读者和用途、术语、重复、标题与引用组织、入口能否帮助定位正文 |
| 指令与执行边界 | 触发条件、前置状态、权限与副作用、停止条件、可核查的验收 |
| 技术事实 | 原始来源是否支撑相邻结论，版本、上下文及适用范围是否一致 |
| 跨 skill 合规与上游状态 | 名称唯一性、嫁接 LICENSE、上游版本变化及相关交叉引用 |

表达审查不自动展开全量联网事实核验或上游同步检查。若发现明显的事实或授权冲突，单列证据与影响；未核实的技术疑点不能当作已证实错误，也不能借润色悄悄改变原意。

### 正确性核验

本轮包含技术事实核验时，按以下顺序进行：

- 先读取文档已引用的原始来源，确认它确实支持相邻结论且版本、上下文一致。
- 对无来源、证据冲突、版本敏感或准备修订的说法，再查官方文档、规范、源码和发行说明等一手来源交叉核对。不为已充分支持的普通定义机械增加检索，搜索结果摘要也不能单独作为证据。
- 将结论记为"已证实 / 与证据冲突 / 证据不足 / 本仓约定"；本仓约定不需要外部来源证明。发现事实修订时单独说明依据和影响，不把内容更正伪装成普通润色。

报告先说明实际覆盖的文件与维度，区分全文阅读、片段抽样和仅检索。按 skill 或共同问题分组，每项给出文件 / 行号、原文依据、影响与建议；区分可核实的冲突和可选择的风格改进，不把个人偏好当成客观错误。保留有价值的正例，并列出“在本轮范围内未发现明显问题”的入口或文档，不用“全部无问题”概括未核验部分。

批量修复前先与用户敲定**改动策略**：哪些含义保持、哪些有依据地调整，是否移动或删除内容，以及是否同步交叉引用。已获批准的范围不重复确认；超出范围或遇到新分歧时再询问。结构性大改仍按 [refactor.md](refactor.md) 分别审阅标题方案与内容迁移表。

## 跨 skill 专项检查

[conventions.md](conventions.md) 里多是"单个 skill 自身要满足的属性"，看一个 skill 就能核。下面这几项不一样——只有把全仓摆在一起、或对照上游才做得出来，所以单独放在审查流程里，不塞进 conventions。

### 嫁接 skill 的上游 LICENSE

来自外部仓库的 skill（README"嫁接自其他仓库"表里的条目、以及 `grafted-skills.json` 里登记的条目）安装到本仓 `skills/` 目录后，skill 根目录下必须保留一份上游的 LICENSE 文件（原名如 `LICENSE` / `LICENSE.txt` / `LICENSE.md` 都可以，按上游叫什么就叫什么）。适配过程允许改正文、改命令、删个人化片段，但不能顺手把上游 LICENSE 删掉——那等于剥版权声明。

审查时对每个嫁接 skill 目录 `ls` 一遍，缺 LICENSE 的列出来；建议从上游对应 commit（参考 `grafted-skills.json` 的 `synced_commit`）补回原文件，不要自行改写或换成别的协议。

### 嫁接 skill 的上游同步状态

对照 `grafted-skills.json` 里登记的 `repo` / `synced_commit`，看上游从这个 hash 到 HEAD 之间有没有重大更新（新功能 / breaking change / 文档结构调整 / 依赖升级 / 删/改了本仓在用的脚本或 reference）。

走 GitHub API 看 `compare/<synced_commit>...HEAD` 的 commit 数和改动文件清单；如果上游路径就是 `grafted-skills.json` 里的 `path`，只关心这个子目录下的变动即可。

本检查项**只汇报**：列出"自 `synced_commit` 起累计 N 个 commit、影响 M 个文件，看起来有/没有 breaking 改动"，是否 re-graft 由用户决断；审查回合**不要**自动 sync 上游、不要改 `synced_commit`、不要改 skill 文件。

### frontmatter `name` 全局唯一

`.curated/`、`.experimental/`、`.legacy/` 和嫁接根目录加起来不能有重名。Hermes 按 `name` 去重，first-seen wins，后者会被悄悄丢弃。如果同名 skill 落在同一个 external_dir 的不同子目录下（如 `skills/pdf` 和 `skills/.experimental/pdf`），谁先被扫到取决于文件系统遍历顺序，**行为不确定**。

审查时 grep 所有 SKILL.md 的 `name:` 字段，发现重名就报告。
