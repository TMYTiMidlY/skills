# 重构 / 打磨已有文档

把一篇已成型的 skill 文档（SKILL.md 或 reference）做**结构性**重排 / 打磨：理顺标题树、章节归属、来源与信息组织，且**一个字的信息都不丢**。不是重写内容。

适用：用户要"重构 / 打磨 / 审阅结构 / 理顺章节"一篇较长文档。与「审查现有 skills」不同——那是跨多 skill 的合规扫描、只报告；这里是对**单篇**深度改，且**先出大纲、批准后才动手**。

## 四步

### 通读建现状图

读**整篇**（不是只扫标题），列出**现有标题树** + 每节一句话主旨。没有这张现状图，后面无法核对"某节内容挪去哪了 / 有没有漏"。

### 诊断

对照 [checklist.md](checklist.md) 的要求逐条过，找结构问题。重构里最常撞的几项（点进 checklist 看正反例）：

- 标题夹结论 / 计数 / 排名、口语设问、自造术语、带序号 / §N 互引 → checklist「标题命名」。
- 来源引用 / 置信度堆在文末附录、对不上正文 → checklist「每条说法有据、来源与置信度就近」。
- 一节塞两个独立主题（该拆）、同一主题散在多处（该并）→ checklist「渐进式披露三层完整、分工清晰」。
- 私有路径 / 凭据 / 主机名未脱敏 → checklist「个人配置不入 skill 正文」。

### 产出「改后大纲」供审阅（硬闸门）

**批准前不改任何文件。** 先给用户一份**改后大纲**，四要素齐备：

- **缩进标题树**：新的 `##` / `###` 按层级缩进列出，一眼看清层次。
- **每个新节标 `← 来源`**：指明内容来自现有哪节（现标题名或临时"现§N"皆可，审阅时不歧义即可）。
- **内容动作备注**：这块要**挪 / 拆 / 并 / 精简 / 删（附理由）/ 降级为附录**——写清去向。
- **全覆盖**：现有每节都要在大纲里有去处；**要删的显式写出来**（`← 现X 删，因与 Y 重复`），让"丢信息"无处藏。

大纲里的 `现§N` 只是审阅临时指代，不进最终文件（文件仍去编号）；大纲里的新标题本身也要过 checklist「标题命名」。用户逐条敲定后再进下一步。

### 批准后执行

- 按批准的大纲逐块搬内容；**信息不丢**（拿现状图逐节勾）。
- 改带显式锚点 `<a id>` 的标题**只改文字、不动锚点**（见 checklist「引用状态」的章节级锚点条）。
- 改完校验：站内 `[x](#id)` 与 `<a id>` 一一对应、跨文件锚点命中、无残留 §N / 编号标题。
- 大改动逐条与用户确认，别批量改完再问。
