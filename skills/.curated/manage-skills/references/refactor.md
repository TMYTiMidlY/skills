# 重构已有文档

重构适用于已经成型的 `SKILL.md` 或 reference：核验事实，理顺标题树、章节归属、来源和信息组织。原文每条可独立移动的信息都要有唯一去向，同一知识在最终文档只保留一个完整落点；有证据表明内容错误或过时时，可以记录理由后修正或删除。重构不是只换措辞，也不要求把错误、过时或重复的句子原样保留。

这套流程针对单篇文档的深度修改。跨多个 skill 的合规扫描走 [review.md](review.md)；单篇重构必须先提交改后大纲和覆盖台账，获得用户批准后才改文件。

## 流程

### 通读并建立现状图

读完整篇正文，而不是只扫标题。记录现有标题树、每节主旨，以及其中可独立移动的一条结论、步骤、配置、示例或排障信息；下文把这类内容称为"信息单元"。

给信息单元分配仅用于审阅的临时标识，并同时记录：

- 当前所在章节及其作用。
- 与其他位置重复、互补或冲突的关系。
- 可外部核验的事实陈述，以及正文附近对应的引用块和来源。

临时标识只服务于覆盖核对，不写进最终文档。

### 正确性核验

按下面的步骤逐条检查事实：

- 先读结论附近的引用块，再打开其中的原始来源，确认来源支持的是这条结论本身，并核对上下文、版本和适用条件。
- 再联网搜索一手来源交叉核对，优先官方文档、规范、源码和发行说明；搜索结果摘要和互相转载的二手文章不能单独作为证据。
- 将每条结论标为"已证实 / 与证据冲突 / 证据不足 / 本仓约定"，记录来源版本或检索日期。
- 多个互相独立的主题可以并行核验，但最终由同一执行者统一术语、证据标准和冲突处理。

事实与来源冲突、证据不足，或核验结果要求改写原结论时，把它列为独立的内容修订，说明证据和影响，交给用户确认；不要把事实变化混进结构润色。

### 结构诊断

对照 [conventions.md](conventions.md) 的全部要求检查现状图，重点判断：

- 术语是否清楚，章节是否先交代范围再进入细节，是否存在空话或同义反复。
- 同一主题是否散落多处，单节是否混入可独立维护的第二个主题，三层渐进式披露是否分工清楚。
- 标题是否夹带结论、计数、排名、口语设问、自造术语或序号式交叉引用。
- 事实、建议和本仓约定是否混写，来源与置信度是否贴近对应结论。
- 命令、配置、脚本、图形界面步骤和视觉材料的呈现形式是否适合其用途。
- 私有路径、凭据、主机名和个人配置是否完成脱敏。

诊断时同时确定每项重复信息的主位置。不能只发现遗漏风险而不处理重复。

### 改后大纲与覆盖台账

**用户批准前不修改文件。** 改后大纲应包含：

- 新的缩进标题树，使层级和章节边界一眼可见。
- 每个新节的来源信息单元，以及要执行的移动、拆分、合并、精简、修正或删除动作。
- 正确性核验发现的内容修订、证据状态和待用户决定的冲突。
- 原文到新文的覆盖台账：每个信息单元必须恰有一个去向；删除项必须写明理由。
- 新文到原文的反向核对：每个新节标明来源；同一信息单元出现在多个新位置时，视为待消除的重复。

可以按下面的代码环境表达单个大纲节点，避免把示意写成真实标题或链接：

```text
新标题
← 来源：现-03、现-07
动作：合并重复定义；保留现-07 的例子
核验：结论已证实；来源锁定到 <版本或提交>
```

新标题本身也要符合 conventions 的「标题命名」。用户批准大纲、覆盖关系和事实修订后再执行。

### 执行与双向核对

- 按批准的大纲逐个处理信息单元，不顺手扩大范围。执行中发现新的事实冲突或结构分歧时，暂停对应部分并重新确认。
- 用覆盖台账正向检查原文每个信息单元都有去向，再反向检查新文没有无出处新增的事实性内容和重复落点。
- 对照核验记录确认已批准的事实修订全部落实，证据不足的内容仍保留不确定性说明。
- 改带显式锚点 `<a id>` 的标题时只改文字，不动锚点；检查站内链接、跨文件链接和锚点目标。
- 最后对照改动 diff 与批准的大纲，确认没有遗漏、重复或范围外修改。
