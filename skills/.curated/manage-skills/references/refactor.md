# 重构已有文档

## 适用范围

本流程用于深度重构一篇已经成型的 `SKILL.md` 或 reference：核验事实，理顺标题树、章节归属、来源和信息组织。跨多个 skill 的合规扫描走 [review.md](review.md)，不使用本流程。

重构以语义不漏为准，不要求逐字保留原文。重复内容可以合并；错误、过时或证据不足的内容可以在说明依据并获得批准后修改或删除。结构调整与事实修订必须分开标明，所有含义上的删除、新增和修改都要进入改前方案；不改变含义的措辞润色由最终 diff 核对。

改文件前分两轮审阅：先批准标题方案，再批准内容迁移表。两轮都通过后才执行，已经批准的改动不重复确认。

## 原文分析

这一阶段先还原原文的结构、内容和证据状态，再据此设计标题与内容的去向。不能只扫标题，也不能先写新文再反推原文去了哪里。

### 原文盘点

先通读全文，列出原文标题树，并用一句话说明每节的作用。只有需要拆分、合并、去重、删除或事实核验的部分，才继续细分为可独立处理的信息项。

每个信息项记录：

- 当前标题路径及其在原文中的作用。
- 与其他位置重复、互补或冲突的关系。
- 附近已有的引用块、来源和可外部核验的说法。

优先用标题路径指代来源；同一节需要拆成多个信息项时再分配临时标识。临时标识只用于改前核对，不写进最终正文。

### 事实核验

事实核验先利用原文已有来源，再把外部搜索集中到会影响重构决定的说法上，避免把单篇重构无差别扩成全面审计。

- 先打开结论附近的原始来源，核对它是否支持该结论，并检查上下文、版本和适用条件。
- 对无来源、版本敏感、互相冲突、准备修改或删除的说法，再查官方文档、规范、源码和发行说明等一手来源。搜索结果摘要和互相转载的二手文章不能单独作为证据。
- 将需要核验的信息项标为“已证实 / 与证据冲突 / 证据不足 / 本仓约定”，并记录来源版本或检索日期。本仓约定只需标明性质，不做无意义的外部搜索。

与证据冲突、证据不足或需要改变原结论的信息项写进内容迁移表，附上证据和影响后逐项询问用户。证据不足不预设保留或删除。

### 结构诊断

事实边界明确后，对照 [conventions.md](conventions.md) 的全部要求检查原文。这里不重抄具体写作规则，只补充重构特有的判断：

- 章节边界是否清楚，同一节是否混入可独立维护的其他主题。
- 同一知识是否散落多处，以及完整解释应放在哪个主位置。
- 事实、建议和本仓约定是否混写，来源与置信度是否贴近对应说法。
- 每个标题区块是否满足 conventions 对开头承接和结尾收束的要求。

诊断必须同时处理遗漏和重复：既要确保原文信息都有去向，也要避免同一知识在新文中反复完整解释。

## 改前方案

改前方案分为标题方案和内容迁移表，两者分别审阅。用户批准前不修改文件；后续内容分析若要求改变已批准的标题结构，先返回标题方案重新确认。

### 标题方案

标题方案先展示改后标题树，再附标题调整表。

标题树不用列表符号，只靠缩进和每行保留的 `#` 数量表示最终层级，并将 H1、H2 行加粗。新标题本身必须符合 conventions 的标题命名要求。

标题调整表逐项记录原标题路径、改后标题路径、调整方式和理由，覆盖保留、重命名、层级变化、拆分、合并、删除和新增。每个原标题都必须有去向，每个新增标题都要说明理由。标题方案单独获得批准后，再进入内容迁移表审阅。

### 内容迁移表

内容迁移表只用于改前核对，不写进重构后的正文。它逐项记录原文信息最终放到哪里、哪些重复内容合并、哪些内容删除或修改及其原因，也记录有实质含义的新增内容。

每项至少包含：

- 原文位置或新增依据。
- 一个承载完整解释的主去向，以及必要的引用位置。
- 保留、移动、拆分、合并、删除、修改或新增等处理方式。
- 处理理由、证据状态和仍待用户决定的问题。

同一知识只保留一个完整解释的主去向，其他章节可以简短引用结论或链接到主位置。引用位置不算重复落点；在多个位置重复展开同一内容才需要合并。

内容迁移表要同时做两个方向的核对：原文每项信息都有主去向或明确的删除理由；新文每项实质新增都有来源或依据。事实核验造成的删除、修改和新增直接记录在表内，不另建重复清单。纯措辞润色不逐句登记，由用户查看 Git diff。

内容迁移表中的未决冲突逐项确认，整张表单独获得批准后才开始修改文件。

## 执行与核对

执行阶段只落实已经批准的标题方案和内容迁移表。发现新的事实冲突、结构分歧或范围外的含义变化时，先更新对应方案并重新确认，不顺手扩大范围。

完成修改后：

- 从原文到新文核对每项信息的主去向、引用位置或删除理由。
- 从新文到原文核对实质新增的来源，确认没有无依据内容或重复的完整解释。
- 对照事实核验结果，确认每项删除、修改和新增都符合用户决定。
- 改带显式锚点 `<a id>` 的标题时只改文字，不动锚点；检查站内链接、跨文件链接和锚点目标。
- 清除只用于审阅的临时标识，确认没有编号标题或序号式章节引用。
- 对照最终 diff、标题方案和内容迁移表，确认没有遗漏、重复、范围外修改或未记录的含义变化。

最后向用户汇报实际删除、新增、因事实核验而修改的内容，以及执行结果与批准方案之间的偏差。纯措辞变化留在 Git diff 中供用户查看。
