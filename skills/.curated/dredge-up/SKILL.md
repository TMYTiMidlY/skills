# dredge-up — 会话收尾盘点

用户准备结束或交接会话时，回顾**已经完成的事项**和**讨论或承诺过但尚未完成的事项**。

长会话里的早期对话可能被压缩或截断。盘点需要回读原始记录，找出被后续任务打断或遗漏的要求，不能只复述当前上下文中的印象。

## <a id="session-source"></a>会话来源与标识

开始读取前，先确定目标会话来自哪个工具，以及它的会话 ID。

- **用户只给出会话 ID、没有明确说明来源工具时，必须先向用户询问并等待回答，再读取或检索。** 例如：“这个会话 ID 来自哪个工具：Copilot CLI、Claude Code、Codex、DSH，还是其他工具？”不要根据 ID 形状、当前运行环境或默认搜索结果猜测，也不要先跨工具搜索来代替询问。
- 用户明确指定的目标会话优先。只有用户要求盘点“当前会话”时，才使用运行时明确提供的来源和 ID；任一信息不明确就询问。正文中提及的历史会话 ID、文件名或子代理 ID，不自动成为盘点目标。
- 确认来源后，所有按 ID 读取或搜索的命令都加 `--agent <agent>`。`asmgr` 的来源标识包括 `copilot`、`claude`、`codex`、`dsh` 和 `chatgpt`；ChatGPT 仅使用已经导入本机的快照。ID 为前缀时，在该来源内核对唯一匹配，不直接采用第一条结果。

## 盘点依据

你当前的上下文是**有损**的：长会话早期对话被压缩，用户某句"顺便把 X 也改了"可能已经不在你视野里。所以单一信源都不够，必须**多源交叉**：

1. **本 session 的原始 turns / 事件流**（最重要）——回读本机 session 状态目录里的存档，逐条看用户**实际说过的每一句话**，而不是你记得的版本。这是唯一能抓出"压栈遗忘"项的办法。
   - 确认来源后，用本机 `asmgr` 通读：`asmgr show <id> --agent <agent> --format dialogue`。主干保留可恢复的用户消息、提问与选项、回答、压缩摘要和助手正文，**不显示普通工具调用及结果**；需要某步工具细节时再用 `--format text`。
   - **用户的选择和自由回答也算对话内容**：核对问题、候选项和实际回答，不要只数普通用户消息。不同来源能恢复的内容不同；工具提示缺失时，不能推断用户做过某个选择。
   - **只读本机、不碰云端**：使用已确认工具的本地会话存档或 `asmgr`，不调用云端会话检索。跨会话检索也限定来源：`asmgr search "<关键词>" --agent <agent>`。
   - 最新一轮可能尚未落盘；可用当前上下文补充，并注明这部分尚未在存档中核实。
2. **计划与待办**——核对该工具实际保存的计划、任务清单或待办记录；有 `plan.md` 时再读取，不假定所有工具都使用同一目录或 SQL 表。
3. **真实世界状态**，别凭印象：
   - `git status` / `git log`：有没有改了没 commit、commit 了没 push 的。
   - 文件系统 / 远端实况：服务真起了吗、远端真部署了吗（走 portal）。
   - **grep 验证承诺**：用户要的功能，代码里真有对应实现吗？（典型坑：文档/配置描述了一个开关，但 `grep` 发现代码里一个标识符都没有——等于没做。）

## 工作流程

1. **确认来源并回读对话**：先按[会话来源与标识](#session-source)确认工具和 ID，再跑 `asmgr show <id> --agent <agent> --format dialogue`。逐条检查每件要求是否完成、是否只做了一部分、是否被后续任务打断；需要工具细节时再用同一来源的 `--format text`。
2. **交叉核对状态**：对照实际存在的计划与待办、`git status`、文件系统和远端状态，确认每件完成事项已经落地。
3. **grep 验证关键承诺**：凡是"实现了某功能"的结论，回去 `grep` 确认代码/配置真的存在、真的生效，不要只凭你说过"我改好了"。
4. **按下面的范式输出盘点报告**。
5. **可选交付物**：用户要交接或留档时，写交接文档或导出 HTML，见[可选输出](#exports)。

> 定时盘点须预先明确来源工具和会话 ID。缺少来源时仍要询问，不能因无人值守而默认选择工具。

## 输出范式

参考用户过去最满意的几次收尾盘点提炼（详见 [references/examples.md](references/examples.md)）。结构：

### 已完成事项
按编号或时间列，每条带状态标记（✅ 已落地 / 🟡 做了一半 / 本地未推 等）。简洁，要点即可。

### 未完成事项
这一节是用户真正要的。每条必须给齐：
- **是什么**（一句话）
- **严重度**：🔴 高 / 🟡 中 / 🟢 低
- **来源**：用户哪次说的、为什么漏了（如"被后续任务压栈"）
- **需要你决策的具体问题**：给出可选项（A/B/C）或具体命令，不要含糊地"建议看看"。
  - 凡涉及 `git add/commit`、push、发布、删分支、删文件等**有副作用**的动作，列出来让用户拍板，**不要自动执行**（遵守工作区 Git/发布/删除规则）。

### 排障经验（可选）
本 session 踩过但还没记进任何文档的坑。若有价值，提示用户是否要补记（如交给 `mess` skill 归档）。

### 交接提示（仅交接时）
下一个 agent 看不到本会话上下文，列出：唯一交接物路径、用户已钉死的决策（"两次否决了 X，别再碰"）、易踩的坑。

### 敏感信息说明（涉敏时）
若本 session 碰过密码 / secret / 凭据，简短说明你是否接触过明文、敏感文件落在哪、是否需要清理。

### 会话名称建议（可选）
盘点末尾给一个**会话名建议**，方便用户回头检索：**kebab-case、用 `-` 连接、3–10 个词、不必符合语法**，抓住这次会话干的主线即可（如 `asmgr-dialogue-view-askuser-decision-extract`）。⚠️ `asmgr` 只读、**不写**会话名——只给建议，由用户使用对应工具的会话改名入口处理。

## <a id="exports"></a>可选输出

- **报告式存档（导出 HTML / Markdown / 文本 / JSON）**：用户要可视化留档 / 把会话交给别人时，用 **`asmgr`**（`agent-session-manager` 仓库的 CLI）导出。本 skill **不再自带渲染器**——同一套解析+渲染逻辑只在 `asmgr` 里维护一份。
  - **准备工具**：`asmgr` 是单一无 scope 的 npm 包，命令同名，安装命令为 `npm i -g asmgr`。也可使用 Releases 中的原生二进制；安装本身不属于只读盘点，工具缺失时先说明情况。
  - **单文件 HTML**：`asmgr html <id> --agent <agent> -o out.html`。报告支持离线搜索、类型筛选、折叠、目录、代码高亮和数学公式。用户提供明确的本地会话文件时，可用 `asmgr html --file <路径> -o out.html`，由工具检测格式。
  - **Markdown**：`asmgr md <id> --agent <agent> -o out.md`。
  - **对话主干通读**：`asmgr show <id> --agent <agent> --format dialogue`，用于回读用户消息、可恢复的交互式问答、压缩摘要和助手正文；普通工具调用及结果不展示。
  - **完整文本 / 结构化 JSON**：`asmgr show <id> --agent <agent> --format text`；需要结构化数据时改为 `--format json`。工具、子代理、计划等细节以该来源实际保留的内容为准。
  - **附加总结**：`asmgr html <id> --agent <agent> -s 总结.html` 使用 HTML 片段；`asmgr md <id> --agent <agent> -s 总结.md` 使用 Markdown。两种格式不能混用同一片段，需要时查看 `--summary-format`。
  - **来源与保真度**：各工具的持久化格式和可恢复条目不同，不能把某一工具的字段规则套到其他来源。缺失内容和有损回退须在报告中注明；离线归档不等于可继续运行的原生会话。

  > Copilot 的 `events.jsonl` 缺失时，`--copilot-db <session-store.db>` 可从 `turns` 表回退，但只有用户和助手文本，无法恢复交互式决策与工具条目。Bun 原生二进制缺少该 SQLite 回退能力；DSH 压缩日志也需要运行时支持 Zstandard。具体限制见 [asmgr 使用说明](https://github.com/TMYTiMidlY/agent-session-manager/blob/v0.3.0/README.md#L35-L99)与[归档保真度说明](https://github.com/TMYTiMidlY/agent-session-manager/blob/v0.3.0/docs/adr/0003-archive-reconstruction-fidelity.md#L7-L25)。
- **正式交接文档**：若用户明确要"交接给下一个 agent / 写 handoff"，结合 `plan` skill（写给实施者的自包含正式文档）或仓库自带的 handoff 流程，不要在本 skill 里重造。

## 关于导出工具

导出与会话解析由 `asmgr` 维护，本 skill 负责确认会话来源、回读记录和核对事项。Copilot CLI、Claude Code、Codex、DSH 及本地导入快照的具体支持范围，以已安装版本的说明为准；读取失败时报告原因，不自行补造记录。

## 边界

- 本 skill 只**盘点和报告**，不替用户做有副作用的动作。所有 commit / push / 发布 / 删除都列成待办让用户决策。
- 不臆造"做过的事"——拿不准就标"待验证"，并去 grep / 查状态坐实。
